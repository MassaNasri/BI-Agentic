## SQLite classification

The discovered SQLite configurations belong to AI, Connector, Detector, Extractor, Transformer, Loader, and Metadata Django scaffolding. Thirteen stopped-container files and one local file were integrity checked in Phase 0 and contained no tables. Current durable business state is in PostgreSQL, ClickHouse, SurrealDB, Metabase PostgreSQL, named media/upload volumes, Kafka/ZooKeeper, and Redis—not these SQLite files. They remain disposable/test or development-only and are not falsely promoted to permanent state.

## Version/reproducibility pins

All stateful or recovery-sensitive third-party images in the root Compose definition are digest pinned: PostgreSQL 18.3, Metabase v0.58.8.5, SurrealDB 3.0.1, ClickHouse 26.2.3.2, Kafka/ZooKeeper 7.5.0, Redis, ClamAV, and Kafka UI. The five Kafka/ZooKeeper named targets were populated before Compose adopted them, so this workstation emits a harmless “not created by Compose” ownership-label warning; the declared names and mounted data are deterministic, and their anonymous sources remain available for rollback.

The earlier SurrealDB process used the memory engine and was already stopped before Phase 0. Its former memory-only records are unrecoverable. P0-B proves durability and recovery for new records only and does not claim to reconstruct lost historical metadata.
